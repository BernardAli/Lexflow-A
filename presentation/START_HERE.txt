ANALYTICS EXTENSION

Open Overview > Pilot analytics. All four report tabs use the same receipt-date,
workflow, source and demo/live filters:
- Summary: six KPI cards, daily/confidence charts and workflow drill-downs.
- Extraction and review: first-extraction coverage, current field review state,
  changed fields, source methods and pending scan acknowledgements.
- Workload and timing: median/P90 elapsed durations with sample counts, age bands,
  sources, paginated case links and recorded reviewer actions.
- Delivery and audit: connector outcomes/retries, pending receipts and audit checks.

Expand View chart data for exact values or export the applied report as CSV.
The CSV contains aggregate metadata, without source text or extracted case values.
Confidence scores are heuristic. Approval time includes waiting; staff handling
time and manual re-keying errors require separate measurements. No savings are
inferred. Synthetic values remain separate from live-office results.

WHAT THE BUILD NOW SUPPORTS

- Local digital PDF/text and OCR for scanned PDFs/images, with explicit review.
- Remote scanner/saved-email intake using only the office API token.
- Conflict handling, source-linked corrections and role-based frozen approval.
- File export and authenticated HTTP handoff with safe idempotent retries.
- Encrypted private data, signed audit state and independent audit checkpoints.
- Encrypted backup/restore with source, private-field, approval and export checks.
- PostgreSQL row-lock tests and reproducible synthetic acceptance drills.
- Four filtered analytics tabs, chart data tables, case links and aggregate CSV.
- Section tabs with keyboard/deep-link support, password visibility and reset.

PLUGIN AND DESTINATION ROADMAP

Current: intake/case-read API, remote scanner/saved email, approved XML/JSON/CSV
exports and authenticated HTTP handoff. The reference receiver is synthetic-only.
Planned: integration setup/status and connection tests; separate scoped plugin
credentials; versioned per-destination mappings; automatic background delivery.
Then build native Outlook intake and one actual office-selected vendor adapter,
followed by Word template filling and the office's chosen cloud document source.

Confirm the destination product/version, documented interface, credentials, schema,
sandbox and durable acceptance/receipt before implementation. Native Outlook/Word,
cloud-storage plugins and named vendor adapters are not supplied by this build.
The current single office token permits intake AND case reads; rotating it affects
every client. HTTP configuration is operator-managed, not a self-service catalog.

WHAT STILL NEEDS CLIENT ACCEPTANCE

The actual vendor interface/import and receipt; hosted containers/TLS/operations;
representative sanitized office samples and measured manual baseline; agreed
scope and compliance review. Native Office plugins, SSO and additional hosting
models remain roadmap scope. No legal certification or customer savings are claimed.
