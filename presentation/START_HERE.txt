STRUCTURED CASE / PRONOTAR32 EXTENSION WALKTHROUGH

Use a separate unapproved synthetic case for this extension; saved additional
details make legacy XML/JSON/CSV exports unavailable for that case.

1. Sign in as admin. In Connectors choose Enable structured case exports. This
   adds one Case JSON download destination per active workflow. A fresh or reset
   demo needs this step; repeating it does not duplicate configured destinations.
2. As a reviewer, open a classified case and choose Case details · parties and
   properties. Add an office designation/code, a second buyer or company, and a
   second property. Enrich primary records with register/tax/contact details.
   Edit source-bound primary values in Extracted data.
3. Show Export readiness. It reports local mapping errors, not vendor acceptance.
   Complete source review, resolve conflicts and confirm the purchase price.
4. As keller.notar, approve and choose Case JSON — Property purchase. Download
   the JSON and show participants[], properties[] and the frozen mapping version.
   The case details are locked. Download alone does not prove delivery.
5. In Connectors show LexFlow case JSON v1 as available and ProNotar32 as not
   implemented. Explain that its exact version, import contract, accepted sample
   files and vendor test environment are the next inputs.

The API at GET /api/v1/matters/<ref>/approved/ reads the complete frozen case using
the office token. It does not apply a destination mapping or send the case.

ANALYTICS EXTENSION

Open Overview > Pilot analytics. All four report tabs use the same receipt-date,
workflow, source and demo/live filters:
- Summary: six KPI cards, daily/confidence charts and workflow drill-downs.
- Extraction and review: first-extraction coverage, current field review state,
  changed fields, source methods and pending scan acknowledgements.
- Workload and timing: median/P90 elapsed durations with sample counts, age bands,
  sources, paginated case links and recorded reviewer actions.
- Delivery and audit: connector outcomes/retries, pending receipts and audit checks.

Expand View chart data for exact values or export the applied report as CSV.
The CSV contains aggregate metadata, without source text or extracted case values.
Confidence scores are heuristic. Approval time includes waiting; staff handling
time and manual re-keying errors require separate measurements. No savings are
inferred. Synthetic values remain separate from live-office results.

PLUGIN AND DESTINATION ROADMAP

Current: intake/case-read API, remote scanner/saved email, approved XML/JSON/CSV
exports, canonical case JSON, frozen destination mappings, an approved-case API
and authenticated HTTP handoff. The reference receiver is synthetic-only.
Planned: integration setup/status and connection tests; separate scoped plugin
credentials; automatic background delivery and native Office/cloud integrations.
The immediate vendor extension is ProNotar32 against its documented contract and
accepted fixtures. Existing XML import buttons do not supply that specification.

Confirm the destination product/version, documented interface, credentials, schema,
sandbox and durable acceptance/receipt before implementation. Native Outlook/Word,
cloud-storage plugins and named vendor adapters are not supplied by this build.
The current single office token permits intake AND case reads; rotating it affects
every client. HTTP configuration is operator-managed, not a self-service catalog.
